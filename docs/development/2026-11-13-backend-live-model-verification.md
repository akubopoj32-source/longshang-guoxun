## 背景与结果

验证小程序和桌面端共用的 Python 后端能实际调用图文模型，保存模型线索、原始照片和巡查记录。四轮真实请求均写入 `extraction_mode=model`，耗时 5.4～6.8 秒。图片为项目自制的诱捕器示意图，文字为模拟巡查描述。

## 接口和数据兼容性

验证使用现有接口。`GET /api/health` 返回 `ok`，`GET /api/config` 返回 `mode=model`。通过 `POST /api/records` 创建 `trap` 任务，再向 `POST /api/records/{id}/turn` 提交文字及照片，每轮带上当前 `version` 和 `status`。完整记录中的 `turns` 可核对模型执行方式、原图和视觉线索。小程序格式 `?view=mobile` 返回字段、照片数量和复核意见。

## 合并与交接

本次为联调记录，客户端可按[项目运行说明](../../README.md#微信小程序联调)复现。复测时先确认共享服务处于模型模式，再用 `evaluation/fixtures/` 的图像按表中输入提交。模型输出可能变化，验收时分别核对原图留存、字段、追问与冲突提示。

后续需复测常见口述里的数量能否稳定写入独立字段。真机拍照上传和真实巡查图像的识别效果需单独验证。本次双端复核状态通过 API 验证。
