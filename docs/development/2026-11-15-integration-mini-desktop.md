## 背景与结果

合并队友的小程序搜索、证据查看、逐字段复核、导出和录音转写代码，保留主线的 SQLite 存储、知识库、桌面端工作台和连接恢复。两端使用同一个服务、数据库和记录 ID。手机端可以看到退回意见、补充证据并再次提交，桌面端可以继续复核和输出复查单。

更正字段后，旧原话保留并标注为已被更正，当前数量告警仅使用仍有效的同轮证据。小程序列表和详情只传递照片是否存在，点击轮次按钮时下载原图。详细 JSON 导出仍可以包含原图。

## 接口和数据兼容性

桌面端原有记录和知识库接口沿用主线契约。小程序沿用 `?view=mobile`，保留 `turn_count`、`photo_count`、`review_note` 等原有字段，并增加轮次详情、字段证据和复核历史。轮次的 `has_image` 表示可通过 `GET /api/records/{id}/turns/{turn}/photo` 下载原图，沿用访问令牌。详细 JSON 导出请求完整记录。更新时两端仍传 `version` 和 `status`，冲突返回 409。

`POST /api/transcribe` 只返回转写。该路由单独为 Base64 JSON 预留 8 MB 原始音频的编码空间，记录上传的请求限制沿用主线。转写的 `voice` 配置字段不代表模型服务已通过真实音频验证。小程序使用端上临时录音文件，提交后保存的是核对过的文本。

无新增数据库迁移。证据未带 `superseded` 字段时按原有记录读取，新增标记只随新更正保存。如果从主线更新，重启共享服务，并让两个客户端连接同一地址和令牌。旧版小程序仍可使用原有字段。新版小程序的完整功能依赖合并版后端。

## 验证结果

| 验证项 | 操作 | 实际结果 |
|---|---|---|
| 双端流程 | 用小程序同款 API 提交模拟图文，在 Playwright 控制的桌面工作台查看原图并退回，再由小程序接口补拍并提交，最终确认和预览打印 | 同一条记录完成状态流转，两端可读，手机接口读到退回意见 |
| 并发保护 | 在退回态并行提交两个相同版本的补录请求 | 一个返回 200，一个返回 409，数据库只保存一轮 |
| 小程序模块 | 用替身微信运行时驱动实际 JS 模块，读取实时后端数据，下载原图并生成 Markdown 和 JSON | 保留历史证据标记，下载原图通过，JSON 包含原图。原图接口拒绝错误令牌，并对缺失附件返回 404 |
| 知识库与语音 | 检查本地知识检索、未配置模型的返回，以及 8 MB 编码上限 | 知识库返回引用，转写失败提供 503 可处理提示，超限音频被拒绝。实际模型和真机录音转写待验收 |
| 回归 | `python -m unittest discover -s tests -v`、四种 `evaluation.run` 模式、JS 语法检查 | 26 项单测、145 项离线评测断言通过，JS 语法检查通过 |
