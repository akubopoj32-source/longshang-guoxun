## 背景与结果

真机联调已走通手机提交、桌面退回、手机补拍重提及桌面复核。评测使用人工核对过的 AI 模拟图片和固定文字，分别检查纯文本流程、图文模型候选和图文完整流程。用图文请求的同一次响应对照规则应用前后，避免模型两次采样的差异影响这一比较。

## 修改明细

## 接口和数据兼容性

复用当前模型客户端、工作流和本地模型环境变量。每个案例分别为纯文本和图文创建内存记录。图文候选来自完整流程中调用模型的响应，后续轮次共享该流程的上下文。工作台 API、数据库、小程序与桌面构建保持兼容。此次评测使用模拟数据，无需连接真机验收数据库。

字段指标以预设字段和值做精确匹配。无依据填报指标只统计标注应缺省的字段。更正指标核对新值，图文候选另需明确标明更正。完整流程额外检查旧依据是否保留，以及局部视野和跨轮输入是否产生错误的数量差异提示。图片水印和较小案例量限定了本轮结论的范围。

### 正式复测结果

| 对照组 | 字段精确匹配 | 无依据填报 | 更正 | 视觉检查 |
|---|---|---|---|---|
| 纯文本工作流 | 14/14 | 0/7 | 1/1 | 无图，按预期无可见数量或数量差异 |
| 图文模型候选 | 10/14 | 0/7 | 1/1 | 可见数量契约 5/7 |
| 图文完整工作流 | 13/14 | 0/7 | 1/1 | 可见数量和当前轮次差异提示合计 9/14 |

| 案例 | 本轮结果 |
|---|---|
| 完整照片，数量一致 | 模型从照片数出两只。工作流把候选 `2` 恢复为原话「两只」，未报差异 |
| 完整照片，数量冲突 | 照片为两只，口述为三只。模型把数量字段写成「三只疑似虫体」，工作流接受了这段原话，但差异比对目前只识别独立数量，导致漏报 |
| 局部照片 | 模型把局部照片判为完整，并把画面中的一只作为整板数量，导致错误的数量差异提示 |
| 模糊照片 | 保留照片的视野局限，无可见数量。没有补写缺失的时间、数量或观察现象 |
| 误传室内照片 | 无可见数量。没有补写点位、时间、数量或观察现象 |
| 更正点位 | 首轮重复使用局部照片时出现误报。第二轮点位更新为「五号监测点」，保留原「三号监测点」依据和原口述数量。首轮警告留存，未标成第二轮差异 |

初次实测中，图文规则把 4 个无单位的数字候选恢复成了原话，图文字段匹配从 10/14 提升到 14/14。初测有一次局部图判为 `partial`，规则正确拒绝将其用于整板计数。复测中同一张局部图两次都被判为 `complete`。这轮结果用于定位局部视野误判和数量字段格式两个问题。

## 合并与交接

- 本次仅增加评测与文档，两端无需配合升级或迁移。复现前配置本机模型客户端，再从项目根目录运行评测。JSON 明细默认建议存于 Git 忽略的 `local/` 目录。
- 首轮用图像与固定口述文本验证记录逻辑。语音转写端到端已单独经过真机流程，本轮评测未覆盖转写准确率、实地表现或真实虫种识别。
