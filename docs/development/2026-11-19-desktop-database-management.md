## 背景与结果

新版在桌面顶栏提供独立「数据库管理」页。页面显示巡查记录、待复核、已复核及巡查账号数量，按编号、点位、人员和复核状态分页查询。记录入口复用巡查详情和复核工作台。页面支持校验 SQLite 文件、关联和索引，也可在服务运行期间创建快照并查看备份列表。维护仅通过持有本机工作台令牌的本机客户端发起。

## 修改明细

| 文件 | 具体改动 | 原因与影响 |
|---|---|---|
| `orchard_workbench/database_admin.py`、`orchard_workbench/storage.py` | 复用巡查摘要，增加分页、状态统计、校验和快照维护 | 每页返回 20 条摘要。备份先校验临时快照，再发布到单独目录 |
| `orchard_workbench/server.py` | 加入维护接口和本机工作台权限，提供界面能力标志 | 小程序会话和局域网客户端无法使用数据库维护接口 |
| `orchard_workbench/web/` | 增加数据库管理、记录过滤、维护进度、最近备份和返回工作台的操作 | 窄窗口垂直排列两块面板。查看记录前沿用未保存内容确认 |
| `tests/test_accounts.py`、`README.md` | 增加权限、分页、文件校验和备份回归，记录入口 | 便于核对旧记录和验证新的备份路径 |

## 接口和数据兼容性

新增 `GET /api/database`、`POST /api/database/check` 和 `POST /api/database/backup`。接口要求 IPv4 本机环回连接及有效 `X-Orchard-Token`，配置接口的 `database_admin` 用于显示入口。列表只返回已有记录摘要和维护信息，查看完整记录仍使用原接口。数据库架构沿用 v2，无需迁移。快照位于活动库旁的 `<库名>.backups` 目录，格式为标准 SQLite 数据库。小程序页面继续使用现有巡查与账号接口。

## 合并与交接

- 重启共享服务后重新打开桌面端，从顶栏进入「数据库管理」。先核对所用数据库，再创建备份。使用页面显示的备份目录定位文件。
- 恢复数据库时，先停止相应服务，再按 README 中的恢复流程使用备份副本启动。当前界面提供在线检查和快照管理。
