## 背景与结果

原始证据区的大图容易把图像核验推到首屏之外。此次把核验结论放到原话和缩略图上方，保留点击查看原图。遇到同一轮口述数量与整板照片估计不一致的记录，显式并列两项数量，提示人工核对。当前任务的下一步按钮可定位对应输入或核对项。低频管理入口收至顶栏「管理」，知识库出处先显示标题、章节与原文入口，摘要可逐条展开。

## 修改明细

| 文件 | 具体改动 | 原因与影响 |
|---|---|---|
| `orchard_workbench/web/index.html` | 重排顶栏、原始证据和下一步按钮，加入可展开的图像线索 | 优先呈现巡查、核验和复核操作 |
| `orchard_workbench/web/app.js` | 使用当前轮次的 `evidence_alerts` 和 `visible_count` 渲染核验。根据追问或待核对状态设置按钮目标。改用原生折叠展示引用摘要 | 双数量对照对应实际返回的差异，同页可进入相关字段或输入 |
| `orchard_workbench/web/database.js` | 在数据库页与巡查工作台之间更新导航选中状态和返回焦点 | 便于从管理页回到巡查队列 |
| `orchard_workbench/web/style.css` | 调整首屏间距、原话与缩略图布局、管理菜单和出处样式 | 在常见笔记本窗口内提高关键信息可见性 |
| `README.md` | 更新管理、原始证据和知识库的操作路径 | 使运行说明与当前界面一致 |

## 接口和数据兼容性

沿用现有巡查记录、配置、数据库管理及知识库接口。下一步使用 `record.questions` 中现有的追问键。图像区域使用轮次中已存在的 `image`、`visual`、`photo_quality`、`visible_count` 和响应中的 `evidence_alerts`。使用现有 SQLite 数据库，无需迁移。小程序继续使用当前版本及既有接口。退出并从开发版工作目录重新打开桌面客户端即可重新载入界面资源。

## 验证结果

| 验证项 | 操作或命令 | 实际结果 |
|---|---|---|
| 首屏与真实数量差异 | 在独立本地共享服务连接 `qwen3-vl-plus`，以 1366×768 打开工作台渲染页面。输入「今天上午，三号监测点看到三只疑似虫体。」并附 `evaluation/fixtures/synthetic/complete.png` | 首屏包含下一步、图像核验、原话和缩略图。显示口述 3 只、照片估计 2 只及待人工核对。「核对数量差异」选中数量字段，原图可打开和关闭 |
| 局部图与追问 | 新建记录输入「五号监测点看到两只疑似虫体。」并附 `evaluation/fixtures/synthetic/partial.png`，点击「补充观察时间」 | 提示覆盖或清晰度有限，数量对照隐藏，输入焦点跳到描述框 |
| 管理导航 | 展开「管理」，打开数据库管理并通过「巡查工作台」返回。打开人员管理并关闭弹窗 | 菜单显示人员管理、数据库管理和连接状态，进入页面后菜单收起，关闭人员弹窗后焦点回到「管理」 |
| 知识库出处 | 点击「冰雹后巡查」后查询，在真实模型回答旁展开再收起首条摘要 | 默认显示标题、章节和原文入口，摘要可按需展开及收起 |
| 窄窗口 | 使用浏览器将工作台缩至 820 像素宽 | 页面无横向溢出 |
| 回归检查 | `python -m unittest discover -s tests`，对两个改动的 JS 文件执行 `node --check` | 后端测试 40 项通过，JS 语法检查通过 |

## 合并与交接

- 基于数据库管理页之后的 `main` 开发。若队友同时调整导航、复核或知识库布局，合并时检查 `orchard_workbench/web/index.html`、`app.js` 和 `style.css`。
- 页面验收通过浏览器运行桌面端的共享渲染资源，使用独立联调库和模拟图片。Windows Electron 窗口及微信真机未在本次复测。桌面端上线后可用同一演示步骤复验。
