## 背景与结果

巡查员在小程序提交记录后，电脑端需要让复核员快速找到待办，并在同一视野内核对原话、照片和字段。工作台默认打开待复核队列，选中最近待办或上次打开且仍待复核的记录。用户可切换至已退回、已复核、草稿和全部，按任务、更新日期和关键词筛选。数量差异存在时，打开记录会定位到数量字段和最新一条差异证据。

待复核队列在界面可见时每 15 秒尝试更新，也支持手动刷新。后台更新仅替换列表摘要，复核员已打开的记录及正在填写的内容由当前页面保留。手动刷新可在无未保存输入时加载最新详情。确认或退回后，当前记录留在详情，队列随最新状态更新，便于继续处理下一条待办。

## 接口和数据兼容性

沿用 `GET /api/records` 的状态、任务、点位和最近活动时间，状态计数基于全量摘要，日期筛选按客户端本地日期。复核及提交沿用原记录、字段复核和整单复核接口，版本冲突仍由后端处理。SQLite 无需迁移，旧记录仍可读取。小程序团队继续使用现有提交与读取接口。

## 验证结果

| 验证项 | 操作 | 实际结果 |
|---|---|---|
| 队列和多端提交 | 在 Playwright 中打开工作台，再通过小程序使用的共享接口提交一条模拟记录 | 队列自动更新，未保存的字段更正和复核依据仍在。任务、日期、编号筛选正常 |
| 图文核对 | 打开口述 2 只、模拟模型估计图中可见 3 只的记录，切换到无照片的一轮，再跳回差异证据 | 自动选中数量，原图可在适应窗口与原始尺寸之间切换。更正并保存后可以确认整单、预览带原图的复查单 |
| 退回补拍 | 打开只有局部照片的记录，填写退回意见并退回 | 展示照片覆盖有限，不显示数量差异。退回意见在详情顶部，补录入口可用 |
| 桌面入口与兼容 | 使用独立测试数据库执行 `npm start`，并在 Playwright 检查 1400×900 和 820×600 布局 | Electron 读取新界面和记录成功，窄窗无横向溢出，知识库与录入流程通过 |
| 静态与单元测试 | `node --check orchard_workbench/web/app.js` 和 `python -m unittest discover -s tests -v` | 脚本语法检查及 15 项单元测试通过 |

## 合并与交接

- 同步 `main` 后重开源码版客户端。连接源码共享后端时重开工作台可加载新界面。此前已分发的 Windows 安装目录需要重新构建才能随包加载新版界面。
- 使用已标注的模拟记录验收。小程序开发者工具或真机可再从采集入口提交一条记录，检查电脑端待复核数量、证据定位和退回后的补录状态。本次使用小程序同款 HTTP 接口模拟提交。
- 如需回退，可恢复基线的工作台前端文件并重新加载，无需恢复数据库。
