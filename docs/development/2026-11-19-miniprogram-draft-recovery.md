## 背景与结果

此前未上传的文字和照片仅保存在录入页。手机收到超时提示时，服务端也可能已完成写入。新版按服务地址、账号和记录保存本轮文字和照片。断网重开可从首页打开最近的本机草稿，重新联网并刷新后提交。未确认成功的提交沿用原编号。若服务端已保存，重新进入记录时会核对编号并清理本机草稿。

## 修改明细

| 文件 | 具体改动 | 原因与影响 |
|---|---|---|
| `miniprogram/utils/draft.js` | 保存草稿元数据和本机照片文件，作用域包含服务地址、登录账号和记录 ID | 同一手机切换账号时不会恢复另一账号的草稿。照片更换成功或服务确认写入后清理原草稿照片 |
| `miniprogram/pages/index/`、`miniprogram/pages/capture/` | 增加离线草稿入口、已保存提示、结果核对和固定编号重试。复核提交响应超时时读取现有状态 | 退出页面后可恢复文字和照片。保存结果待核对时，保留原输入用于重试 |
| `orchard_workbench/server.py` | 接收可选 `submission_id`，用请求摘要核对重放，复用现有写版本保护处理并发 | 同编号同内容返回已存记录。同编号不同内容返回 409。原图和轮次只写一次 |
| `tests/test_accounts.py`、`tests/miniprogram-draft.test.cjs`、`README.md` | 增加并发、临时图片失效、断网重开与账号隔离回归，说明用户操作 | 可从正常入口复测，Node 测试用微信 API 替身运行小程序页面逻辑 |

## 接口和数据兼容性

`POST /api/records/{id}/turn` 可带 32 位小写十六进制 `submission_id`。编号与原版本、状态、文字、图片和保存模式绑定。所有重试仍经过会话与记录所有权检查。内部摘要保存在原轮次 JSON，无需迁移 SQLite。小程序详情的轮次可读 `submission_id`，供恢复时对账。桌面完整接口仍返回原格式并保留全部业务证据。

旧记录和旧客户端继续使用原路径。新版服务与小程序共同启用编号确认和重试。与旧服务联调时，版本变化后会保留本机草稿并提示核对。账号登录时按账号隔离，旧令牌联调模式按服务及记录保存草稿。

## 合并与交接

- 启动新版共享服务，重新编译小程序并用普通「预览」扫码。用测试账号打开已建记录，录入文字和照片后断网，退出并重开，检查最近草稿。联网刷新后核对保存结果，桌面查看同一记录的轮次数和原图。
