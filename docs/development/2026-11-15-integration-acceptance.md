## 背景与结果

在增加新功能前，使用隔离数据库验收已合并的巡查、复核和导出流程。真实调用发现当前的 `qwen3-vl-plus` 拒绝录音输入。同一百炼工作空间的 `qwen3-asr-flash` 可接受这段音频，因此录音与图文分别配置模型。另修复小程序录音监听可能叠加、同段音频重复插入描述、缺少分享 API 时没有复制回退，以及 Windows 构建复制运行时文件时异常退出。

## 修改明细

| 文件 | 具体改动 | 原因与影响 |
|---|---|---|
| `orchard_workbench/voice.py`、`compose.yaml` | 用 `ORCHARD_VOICE_MODEL` 选择语音模型，沿用同一服务地址和密钥。千问 ASR 采用其 Data URI 和消息格式 | 图文、知识库和转写可同时工作。部署的语音模式由单独的环境变量决定 |
| `miniprogram/utils/voice.js`、`miniprogram/pages/capture/` | 录音管理器只注册一组监听。转写成功后同一段录音不会再次追加。录音中停用保存和提交，转写失败可重试或手工录入 | 多次录音不叠加监听，保存提交时避免截断正在采集的语音 |
| `miniprogram/utils/export.js` | 分享 API 缺失、运行环境无法发送文件时复用复制回退 | 模拟器和不支持文件分享的环境仍可取出内容 |
| `desktop/build.cjs` | 使用 Windows 自带的 Robocopy 复制 Electron 和 PyInstaller 资源目录 | 解决 Windows 本机的目录递归复制崩溃，发布目录包含运行所需资源 |
| `README.md`、`tests/test_voice.py` | 说明双模型配置，并验证语音模型和 ASR 请求格式 | 防止误将图文模型配置当成语音可用 |

## 接口和数据兼容性

`/api/transcribe` 的请求和响应字段保持兼容。`/api/config` 的 `voice` 改为依据明确的语音模型配置。启用百炼语音时设置 `ORCHARD_VOICE_MODEL=qwen3-asr-flash` 后重启后端，Docker 使用同名环境变量。图文和知识检索原有配置、共享记录响应、访问令牌和 SQLite 格式保持兼容，无需数据库迁移。

| Docker 与备份 | 真实构建并运行隔离 Compose 项目，创建记录后重启容器。执行在线 SQLite 备份并检查完整性与跨端已复核记录 | 容器重启后读回原记录，备份完整性为 `ok` |
| 回归 | `python -m unittest discover -s tests`、四种离线评测和 JavaScript 模拟录音与剪贴板回退 | 27 项单测、145 项离线评测断言通过。连续录音监听、权限拒绝和没有分享 API 时的复制回退通过 |
