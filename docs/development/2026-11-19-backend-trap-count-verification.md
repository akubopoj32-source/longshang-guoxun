## 背景与结果

历史评测响应中，模型把口述数量返回为「三只疑似虫体」，原比较器遗漏了与完整照片中两只的差值。另一条响应把只露出一只的裁切照片判成整板，导致误报。

现在数量字段保留明确的数值和单位，并在证据中保留完整原话。比较时检查数量所在的原始语句是否表达明确计数，可以排除模型引文遗漏「约」「没有」等限定的情况。历史长短语可继续读取并参与有依据的比较。诱捕照片有整板候选时，由同一视觉模型另发一次只看图的请求，检查单块粘板四条边是否完整入镜，并单独计数。两次计数一致才进入数量比对。其余照片保留原图和图像线索，提示补拍或人工核对。

## 修改明细

| 文件 | 具体改动 | 原因与影响 |
|---|---|---|
| `orchard_workbench/orchard.py` | 按口述原句规范化明确数量，比较时认可历史长短语。整板候选需要额外图片核验 | 两端继续显示原始证据。边界无法确认、数值不一致或核验超时时提示补拍 |
| `orchard_workbench/extraction.py` | 新增只看图的边界与数量核验。支持调用方限定等待时间 | 核验请求不包含巡查口述、已有字段或第一次计数。仅完整候选发起附加请求 |
| `evaluation/cases.json`、`evaluation/run.py` | 固定离线案例的整板核验结果 | 离线回放继续无需模型和网络 |
| `evaluation/live.py` | 在正常工作流里获取模型候选并记录单轮耗时 | 图文候选仍和完整流程共用第一次模型响应 |
| `tests/test_evidence.py` | 增加长数量短语、歧义、边界裁切和二次核验失败的回归 | 核对原话、旧值、警告及补拍提示 |

## 接口和数据兼容性

沿用现有 `/api/records/{id}/turn` 与 `?view=mobile`，无需更新小程序或桌面界面代码，也无需数据库迁移。`visible_count` 仍为整数或 `null`，`photo_quality` 使用现有的 `limited` 状态。历史记录中的照片和已有计数无回填。完整候选的附加请求最多等待 8 秒，基于工作流开始后 25 秒的预算计算剩余时间，为小程序 30 秒请求窗口留出余量。核验超时会按有限视野保存本轮。

## 验证结果

| 验证项 | 操作或命令 | 实际结果 |
|---|---|---|
| 固定模型响应复现 | 使用上次评测 JSON 保存的两个模型响应与对应 SHA-256 图片，在临时数据库走 POST `/turn` | 修复前复现漏报和误报。修复后，完整图返回「口述 3、可见 2」，局部图无整板可见数和数量差异，两个客户端响应一致 |
| 单元测试 | `python -m unittest discover -s tests` | 30/30 通过，覆盖不确定数量、旧记录、核验失败时的原图保留和更正历史 |
| 三种离线回放 | `python -m evaluation.run` 的模拟图文、模拟文本和规则图文模式 | 每组 8/8 个案例通过，分别通过 38、35、37 项断言 |
| 真实模型首轮 | `python -m evaluation.live --output 'local/评测结果/真实模型对照-2026-11-19-数量与整板核验.json'` | `qwen3-vl-plus` 图文流程字段 14/14，视觉 14/14，更正 1/1。纯文本组有一次网络错误 |
| 真实模型复测 | 同一批 6 个案例，输出 `local/评测结果/真实模型对照-2026-11-19-数量与整板核验-复测.json` | 两个完整流程均通过字段 14/14、视觉 14/14、更正 1/1、无依据填报 0/7，未出现服务异常。图文原始候选仍有失败，整次对照命令退出 `1` |

两轮实测均对完整图返回两只，并正确提示与口述三只的差异。复测中局部图两次被初判为整板。追加的边界核验拦住两次计数，两条记录均保留图像线索并标记覆盖有限。复测的七轮图文耗时约 4.3 至 14.9 秒，数据来自本机评测进程。

## 合并与交接

- 两端更新共享服务后即可使用，旧服务进程或内置旧后端的桌面安装包需重启新版服务或重新构建。共享库模式可保留现有桌面客户端，并连接更新后的服务。
- 复测时分别上传完整粘板图、局部图，并查看桌面和手机的同一条记录。当前已验证两种 API 响应，更新服务后的真机界面仍待复测。二次核验依赖同一个模型的图像判断，评测样本为 AI 模拟图片。
