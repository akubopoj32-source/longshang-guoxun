## 背景与结果

检查了现有本机数据库与小程序联调数据库，两者完整性检查均通过。旧版通过单表保存记录，列表刷新时从含照片的 JSON 重新提取摘要。写冲突依靠比较完整 JSON，数据库忙时缺少可识别的 API 错误。

新增独立列表摘要、活动时间排序索引和写入版本。数据库在同一事务内同步记录和摘要，WAL 允许读请求与写入并行。数据库忙时等待最多约 5 秒，超时返回可重试错误。

## 接口和数据兼容性

保留 `records` 表中的完整记录 JSON。启动时使用 `PRAGMA user_version` 将旧库从 0 迁移到 1，自动备份原库，并在事务中建立摘要表、索引和同步触发器。列表和详情的成功响应、复核状态、公开 `version` 字段及版本冲突 `409` 沿用原有协议。内部写入版本用于防止并发覆盖，也覆盖仅改变状态的复核。写锁超时返回 `503` 与 `database_busy`，其他存储错误返回 `500` 与 `database_unavailable`。

## 验证结果

| 验证项 | 操作或命令 | 实际结果 |
|---|---|---|
| 现有联调库迁移 | 用 SQLite 在线备份复制当前联调库，在副本运行新版服务 | 5 条旧记录的原始 JSON 逐条一致。完整性与外键检查通过，查询计划使用摘要排序索引 |
| 迁移失败 | 对包含无效 JSON 的旧库运行迁移 | 迁移回滚，原记录、版本和备份可供检查 |
| 并发与异常 | 并行提交同一版本的复核。持有写锁时从 HTTP 读取列表、尝试创建，再释放锁重试 | 只有一次复核写入成功，摘要与记录一致。持锁期间读取成功，写入返回 `503`，释放后恢复。过期更新返回 `409` |
| 双端协议 | 通过共享后端创建图文记录，分别请求完整详情及 `?view=mobile` | 两种响应均读取到数量「两只」。完整详情保留图片与原话 |
| 在线备份 | 服务运行时执行 `python app.py --db <现有库> --backup <新文件>` | 副本通过 SQLite 完整性检查，可读取原有记录和摘要 |
| 回归检查 | `python -m unittest discover -s tests -v` | 11 项通过 |

## 合并与交接

更新共享后端并重启即可使用新版数据库。启动前可通过 `--backup` 保存当前库。自动迁移的备份文件与原库位于同一目录。恢复时停止服务，再以备份副本为 `--db` 启动。双端复测时依次确认旧记录列表、图文录入、提交复核和退回意见可读。
